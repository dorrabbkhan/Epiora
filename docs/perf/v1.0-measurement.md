# v1.0 Task 18 — MEANS performance measurement

**Status:** `means_1m` measured 10/10 on the 1,000,000-row deterministic
dataset in all three attempts of the dispatch run. [Attempt
1](https://github.com/dorrabbkhan/Epiora/actions/runs/44485826291/attempts/1)
and [attempt
3](https://github.com/dorrabbkhan/Epiora/actions/runs/44485826291/attempts/3)
failed the existing owner gates on the slow runner class (`import_1m`
medians 101,794.9 / 102,167.6 ms vs the 89,550 ms threshold,
`open_tables_1m` medians 2,898.5 / 2,902.8 ms vs 2,874 ms); [attempt
2](https://github.com/dorrabbkhan/Epiora/actions/runs/44485826291/attempts/2)
— the rerun the owner's v0.3 runner-variance policy (PR #55)
prescribes — passed all gates on identical code. The owner treated
attempt 3 as a real failure under that policy and had it investigated;
the investigation
(<https://github.com/dorrabbkhan/Epiora/pull/94#issuecomment-7010429729>)
found **CAUSE: runner** — the PR's failing numbers match a main commit
that fails the same gates without any of this code — and the owner
accepted the finding on 2026-11-19. `grid_scroll_1m` still failed
10/10 in every attempt with the known 1M-row DataGrid renderer crash;
fixing it is Task 19, not this task.

## Method

- Authoritative run:
  <https://github.com/dorrabbkhan/Epiora/actions/runs/44485826291>
  — `workflow_dispatch` on `v1.0/task-18-means-1m-measurement`,
  `runs=10`, `rows=1000000`, `profile=persistent`, `ubuntu-latest`,
  Chromium (Playwright 1.64.1), production build. Artifact:
  `perf-results` (`results.jsonl` + `summary.md` + `gates.md`). Each
  sample ran in a fresh `chromium.launchPersistentContext` user-data
  dir, deleted after the sample.
- `means_1m` is timed from the `runMeans` call to its promise
  resolution for `MEANS age grp` — `age` is the generated Integer
  column, `grp` the three-level (`alpha`/`beta`/`gamma`) Text column
  (xorshift32, seed `20261105`, `app/perf/gen-csv.mjs`). The scenario
  calls `__clearSnapshotCache()` first, so the measured time is the
  cold path: snapshot load + hash check + MEANS.
- The same run also verifies the spec split changed nothing: the
  existing scenarios' medians stay inside the run-to-run variance the
  owner documented for identical code.

## Threshold (owner gate — "proposal")

Same convention as the v0.3 thresholds: gate compares the median, the
proposal is measured p90 × 1.25. `means_1m` was measured on the two
runner speed classes the investigation documented; the proposal below
is computed off the **slowest** attempt's p90 so the owner's number
absorbs the documented variance:

- **`means_1m`** — measured 10/10 in all three attempts (median/p90:
  2,503.8/2,538.2 ms attempt 3, 2,475.5/2,519.1 ms attempt 1,
  2,075.7/2,098.2 ms attempt 2). proposal: `ms` ≤ p90 × 1.25 =
  2,538.2 × 1.25 = 3,172.75 → **3,173 ms**. (Computed off the fast
  attempt alone it would be 2,098.2 × 1.25 = 2,622.75 → 2,623 ms;
  the owner picks the basis — Task 19 gates the chosen number.)
