# v1.0 Task 18 — MEANS performance measurement

**Status:** `means_1m` measured 10/10 on the 1,000,000-row deterministic
dataset in both perf-job attempts of the dispatch run. The first attempt
failed the existing owner gates on a slow runner (`import_1m` median
101,794.9 ms vs the 89,550 ms threshold); the job rerun — the remedy the
owner fixed in the v0.3 runner-variance policy (PR #55) — passed all
gates on identical code, so the single red run was variance, not a
regression. `grid_scroll_1m` still failed 10/10 with the known 1M-row
DataGrid renderer crash; fixing it is Task 19, not this task.

## Method

- Authoritative run:
  <https://github.com/dorrabbkhan/Epiora/actions/runs/44485826291>
  — `workflow_dispatch` on `v1.0/task-18-means-1m-measurement`,
  `runs=10`, `rows=1000000`, `profile=persistent`, `ubuntu-latest`,
  Chromium (Playwright 1.64.1), production build. Artifact:
  `perf-results` (`results.jsonl` + `summary.md` + `gates.md`). Each
  sample ran in a fresh `chromium.launchPersistentContext` user-data
  dir, deleted after the sample.
- `means_1m` is timed from the `runMeans` call to its promise
  resolution for `MEANS age grp` — `age` is the generated Integer
  column, `grp` the three-level (`alpha`/`beta`/`gamma`) Text column
  (xorshift32, seed `20261105`, `app/perf/gen-csv.mjs`). The scenario
  calls `__clearSnapshotCache()` first, so the measured time is the
  cold path: snapshot load + hash check + MEANS.
- The same run also verifies the spec split changed nothing: the
  existing scenarios' medians stay inside the run-to-run variance the
  owner documented for identical code.

## Threshold (owner gate — "proposal")

Same convention as the v0.3 thresholds: gate compares the median, the
proposal is measured p90 × 1.25. `means_1m` was measured on two runner
speeds; the proposal below is computed off the **slower** attempt's p90
so the owner's number absorbs the documented variance:

- **`means_1m`** — measured 10/10 in both attempts (median/p90:
  2,475.5/2,519.1 ms slow-runner, 2,075.7/2,098.2 ms fast-runner).
  proposal: `ms` ≤ p90 × 1.25 = 2,519.1 × 1.25 = 3,148.875 →
  **3,149 ms**. (Computed off the fast attempt alone it would be
  2,098.2 × 1.25 = 2,622.75 → 2,623 ms; the owner picks the basis —
  Task 19 gates the chosen number.)
