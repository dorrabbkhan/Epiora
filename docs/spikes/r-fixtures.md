# R reference fixture pipeline — can pinned R produce reproducible reference fixtures?

**Status:** go

## Question

Plan Task 5, exercising spec §12.1 ("fixtures generated by R … never
hand-edited") and Review Focus 4 (R package version drift must fail CI):
can an R pipeline generate reference fixtures — starting with the Oswego
2×2 — that a workflow regenerates, schema-validates and drift-checks
deterministically? And should pinning use `renv` or a Docker image?

## Method

- `fixtures/` is an renv project (`fixtures/.Rprofile` sources
  `fixtures/renv/activate.R`); `fixtures/renv.lock` pins R 4.5.2 and the
  packages epitools 0.5-10.1, jsonlite 2.0.0 and renv 1.3.1 with recorded
  hashes.
- `fixtures/generate.R` locates its own directory (so it works from any
  caller cwd), activates the renv project, then builds the Oswego table —
  ate vanilla × ill: 43 ill / 11 well; did not eat: 3 ill / 18 well — and
  calls `epitools::riskratio`, `epitools::riskratio.small`,
  `epitools::oddsratio` (methods `wald`, `midp`, `fisher`), all with
  `rev = "both"` because epitools' table convention is reference row
  first / non-event column first, plus `chisq.test(correct = FALSE)` and
  `fisher.test`. A sanity assertion stops the run if
  `round(risk_ratio, 2) != 5.57` (attack rates 79.6% vs 14.3%).
- The fixture is written by `jsonlite::toJSON(digits = I(17))`: 17
  significant digits so every double round-trips exactly and the 1e-9
  tolerance stays meaningful.
- `fixtures/schema/fixture.schema.json` (draft-07) constrains the
  interface shape `{id, procedure, inputs, expected, tolerance,
  source{package, version, r_version}}` and rejects extra or missing
  fields.
- `.github/workflows/spike-fixtures.yml` (ubuntu-24.04) restores renv,
  runs `Rscript fixtures/generate.R`, installs the schema validator with
  `npm ci` under `fixtures/tools` (ajv-cli 5.0.0 and every transitive
  dependency pinned by integrity hash in the committed
  `package-lock.json`), then validates every fixture JSON with
  `fixtures/tools/node_modules/.bin/ajv`. The find prunes `fixtures/renv`,
  `fixtures/schema` and `fixtures/tools`, and the step prints the fixture
  count and exits 1 when it is zero, so validation cannot pass
  vacuously. Drift is then checked two ways: `git diff --exit-code
  fixtures/` for tracked changes, and `git status --porcelain
  --untracked-files=all -- fixtures/` must print nothing or the step
  exits 1 — a fixture deleted from git or a stray file left by
  regeneration fails too. renv's library dirs (`fixtures/renv/.gitignore`)
  and `fixtures/tools/node_modules` (`fixtures/tools/.gitignore`) are
  ignored and do not trip the guard. Every action is pinned by commit
  SHA; R and Node are pinned by version; all npm packages by lockfile
  integrity hashes.

## Decision

**renv** — pin the fixture environment with `fixtures/renv.lock` (chosen
over "Docker image"). The lockfile records exact package versions with
hashes, bootstrap is one `source("renv/activate.R")`, standard
`ubuntu-24.04` runners suffice, and the same lockfile serves local and CI
regeneration. A Docker image would pin the OS too, but adds a registry
image to maintain for a pipeline whose only system dependency is R
itself, already pinned by setup-r.

## Consequences

- Fixtures regenerate deterministically: byte-identical output across
  local Ubuntu resolute and CI ubuntu-24.04 (both R 4.5.2 + lockfile
  versions).
- Any diff between a committed fixture and its regeneration fails CI
  (run 40783827413), and since fix round 1 so does any untracked file
  under `fixtures/` (`git status --porcelain --untracked-files=all`),
  closing the gap where a fixture deleted from git was invisible to
  `git diff` (demonstrated locally — see Measurements).
- Schema validation cannot pass vacuously: the step prints the fixture
  JSON count and exits 1 when it is zero.
- ajv-cli is no longer a floating global install: `npm ci` under
  `fixtures/tools/` resolves it and all transitive dependencies from the
  committed `package-lock.json` integrity hashes.
- v0.2 engine tests consume `fixtures/2x2/oswego_vanilla.json` under the
  plan's interface; the 17-significant-digit serialization keeps every
  number exact at the 1e-9 tolerance.
- epitools' "(Wald and exact CIs)" was read as: risk ratio → Wald +
  small-sample CI (epitools' two RR methods — there is no exact RR CI in
  epitools); odds ratio → Wald + mid-p exact + Fisher exact CIs, with
  `fisher.test`'s conditional-MLE OR and CI recorded separately under
  `fisher_exact_test`.
- `source.package` names `epitools` as the headline reference; the stats
  functions (`chisq.test`, `fisher.test`) version with R itself, recorded
  under `source.r_version`.
