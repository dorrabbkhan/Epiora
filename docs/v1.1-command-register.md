# Epi Info 7 command and feature register (v1.1 Task 1)

The register of every Classic Analysis command, expression function, Enter check-code command and
function, MakeView field type and module feature in Epi Info 7, each with its Epiora target version.
Machine-readable copy: `crates/epiora-lang/register.json` (consumed by Task 12 and checked by
`node scripts/legacy/register-check.mjs`).

**Source:** `Epi-Info/Epi-Info-Community-Edition` @ `4cd353c62c40b78d9d1f013b0f5a2bb685a5fca6`
(Apache-2.0, decision D2). Vendored reference copies under `crates/epiora-lang/reference/`:

- `Epi.Core.Interpreter/grammar/EpiInfo.Analysis.Grammar.grm` — Classic Analysis (`.pgm`) grammar
- `Epi.Core.EnterInterpreter/grammar/EpiInfo.Enter.Grammar.grm` — Enter check-code grammar
- `Epi.Core.Interpreter/Rules/EpiFunctions.cs` / `Epi.Core.EnterInterpreter/Rules/EpiFunctions.cs` —
  the function-name dispatch tables (the grammars' `<FunctionCall>` is generic; the callable set
  lives in these `case` labels)
- `Epi.Core/Constants/MetaFieldType.cs` — the 28-member MakeView field-type enum

## Conventions

- **status** `supported` — runs at the given version (or is recorded as a note per spec §6.1 for
  output commands with no numeric effect); `planned` — grammar parses it, the interpreter reports
  it with its line and target version; `not_planned` — outside the roadmap, with a reason.
- **version** — the Classic Analysis target version (every `version` ≤ 1.6, the parity milestone).
  For commands that exist in both grammars (`grammar: "both"`) the check-code target is noted in
  the reason when it differs. Check-code-only commands carry the v1.3 check-code engine version.
- **affects_data** — true when the command can change the working view: an unsupported one poisons
  later results ("may differ from Epi Info", spec §6.1).
- **options** — the grammar's option keywords supported at the listed version, not every option
  the grammar accepts; exclusions are named in the reason.
- Counted from the *uncommented* productions only: commented-out rules (full TABLES variants,
  `Menu_*`, alternative SET forms, `<FuncName1>`) are not reachable grammar. The third grammar,
  `EpiMenuCommandPlugin/Grammar/working-menu.grm`, is the menu-command-file format, not a user
  program grammar, and is covered by the COMMANDLINE entry.

**Non-grammar commands.** Spec §5.3 names CANCEL READ and KEYVARS, but the grammar has neither:
Epi Info 7's only CANCEL forms are CANCEL SELECT and CANCEL SORT, and key definitions are inline
per MERGE/RELATE (`<KeyDef>`; `KEYVARS=` appears only as a LOGISTIC OUTTABLE option). Both are
registered as v1.1 commands per the spec, KEYVARS as the session-level key declaration.

**Grammar statements with no Rule class at 4cd353c** (parse, but the open-source build carries no
execution rule): COMMANDLINE, EXIT, FILEDIALOG, the MAP family, NEWPAGE, SYSINFO and the WAITFOR
family. Recorded for completeness; their placement is unchanged.

## Roadmap gaps

Grammar features the platform spec §14 does not place before the parity milestone; every one is
`not_planned` in the register with its reason. If the owner wants any of them inside v1.6, the
roadmap — not just this register — has to change.

| Feature | Where it lands today | Reason |
|---|---|---|
| EXECUTE, WAITFOR, WAITFOREXIT, WAITFORFILEEXISTS | not_planned | Launching OS processes/URLs is impossible in the web app; desktop-only candidate post-1.6. |
| PYTHON…END-PYTHON, R…END-R | not_planned | Embedded script engines are not on the roadmap; R export covers the R story. |
| SQLEXEC, RECORDSET, CONNECTION | not_planned | Arbitrary database connectivity is a connector feature (v2.2). |
| COMMANDLINE | not_planned | `.mnu` menu-command files; Epiora has no menu-command system (also dead grammar upstream). |
| GEOCODE, GETCOORDINATES | not_planned | No geocoding service is on the roadmap. |
| IOCODE | not_planned | Legacy I/O-board field hardware. |
| SENDSMS | not_planned | Messaging is Phase 3 (v3.0 alerts). |
| SYSBARCODE, SYSLATITUDE, SYSLONGITUDE, SYSALTITUDE | not_planned | Barcode/GPS field capture is v2.4 mobile field kit. |
| DEFINE DLLOBJECT/NETOBJECT, ASSIGN `x!y(...)` | not_planned | COM/.NET interop — Windows-only plugin mechanism. |
| DELETE File, DELETE TABLES | not_planned | Epiora never deletes source files or tables. |
| READ file-spec and SQL/ODBC forms | not_planned | Arbitrary file/DB sources need the connector feature. |

## Proposed v1.1 additions

Commands beyond spec §5.3's table that common programs need and that need no later feature. Their
inclusion is exactly what this OWNER REVIEW decides; accepting any of them adds the corresponding
work to Tasks 11–12.

| Command | Why it belongs in v1.1 |
|---|---|
| UNDELETE | Counterpart of DELETE and SET DELETED; restores session-deleted records before WRITE. |
| RUNPGM | §6.1 already sources programs saved inside imported projects; programs chain with RUNPGM. |
| QUIT, EXIT | End a program run; trivial, but real .pgm files use them. |
| SUMMARIZE | Aggregates the working view to a new dataset — composition of the existing aggregate and WRITE machinery. |
| KEYVARS | §5.3 names it; the session key declaration for MERGE/RELATE. |
| CANCEL READ | §5.3 names it ("the other CANCEL forms"); closes the working view. |
| Note-only set (ABOUT, SYSINFO, NEWPAGE, PRINTOUT, TYPEOUT, HEADER, ROUTEOUT, CLOSEOUT, BEEP) | Already the §6.1 behaviour — parsed and recorded as notes; listed so the register marks them supported rather than unimplemented. |

Deferred with reasoning: CALL/CMD/SUB (subroutine machinery — worth pulling into v1.1 only if the
Task 3 corpus shows programs that use them), MATCH (matched case–control tables — a new analysis
procedure, not a cleaning command), DIALOG/FILEDIALOG (need a run-time input UI).
