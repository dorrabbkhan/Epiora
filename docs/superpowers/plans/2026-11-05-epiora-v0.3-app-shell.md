# Epiora v0.3 App Shell Implementation Plan

> **Execution:** run by the Epiora conductor (Claude Code, `CLAUDE.md`) delegating each task to a fresh local Devin session (`/epiora-task v0.3 <N>`) and a fresh review session (`/epiora-review v0.3 <N>`). One task per branch, named `v0.3/task-<N>-<short-name>`. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the first usable Epiora: an installable, fully offline web app (Netlify) and an unsigned, encrypted-at-rest desktop app (Tauri 2) that import CSV/TSV/xlsx/xls/ods into versioned project datasets and run v0.2's FREQ and TABLES from a dialog-driven Analysis workspace with a saved output log of results and receipts.

**Architecture:** A Rust import crate (`epiora-import`, own lazily loaded wasm) and the v0.2 engine (`epiora-core` + new snapshot codec) run in one data worker that also owns the store client. The store is one SQL schema and one set of TypeScript repositories over a minimal `Store` executor with two backends: sqlite-wasm OPFS `opfs-sahpool` in the browser, and native SQLite3MultipleCiphers (`epiora-store-native`, via Tauri commands relayed by a main-thread bridge) on desktop. The React UI (React Aria Components, CSS modules on generated design tokens) talks to the worker only through a typed Comlink RPC.

**Tech Stack:** Rust (toolchain from `rust-toolchain.toml`), `csv`, `encoding_rs`, `calamine`, `sha2`, `serde`, `ts-rs`, `proptest`, `cargo-fuzz`, `wasm-pack`/`wasm-opt`; `rusqlite` on a vendored `libsqlite3-sys` compiling SQLite3MultipleCiphers (`sqlite3mc-src`), `keyring`, Tauri 2, `tauri-driver`; Node 24 LTS + npm; Vite, React, TypeScript (strict), React Aria Components, TanStack Router, TanStack Query, Comlink, `@sqlite.org/sqlite-wasm`, `vite-plugin-pwa` (Workbox); Vitest (+ browser mode via Playwright), Playwright (Chromium, Firefox, WebKit), `@axe-core/playwright`, ESLint, Stylelint; Netlify CLI; R (fixture generation, `renv`-pinned) with `openxlsx2`, `readODS`, and LibreOffice headless for `.xls`. All at the latest release at task time, pinned in lockfiles.

**Spec:** `docs/superpowers/specs/2026-11-05-epiora-v0.3-app-shell-design.md` (all sections), with the v0.2 spec `docs/superpowers/specs/2026-10-30-epiora-v0.2-engine-core-design.md` §3.3, §4.3, §5.1 and the platform spec `docs/superpowers/specs/2026-10-28-epiora-platform-design.md` §7, §11.1, §12.

## Global Constraints

- Product code lives in `crates/` and `app/`; nothing under `spikes/` is imported. Copying the Tauri spike's vendored `libsqlite3-sys` approach into `app/src-tauri/vendor/` is a copy, recorded in `docs/decisions.md`, not an import.
- Licence AGPL-3.0-only on every new crate and on `app/package.json`; `cargo deny check` clean for both Cargo workspaces; npm production dependencies pass `license-checker-rseidelsohn --production --onlyAllow "MIT;Apache-2.0;ISC;BSD-2-Clause;BSD-3-Clause;0BSD;Unlicense;CC0-1.0;BlueOak-1.0.0"`. Rejected outright: GADM data, SQLite SEE, PowerSync.
- Dependencies at the latest release at task time; never pin an older version to avoid an upgrade.
- Rust crates read no clock, no environment and no locale at run time; `clippy::unwrap_used`, `clippy::expect_used`, `clippy::panic` denied outside tests; every failure is a typed error with a stable `code()`; no input may panic.
- Native and wasm outputs are compared bit for bit (snapshot bytes, import results, receipts).
- Timestamps are produced only in the worker (`new Date().toISOString()`), passed into Rust as `RunContext.timestamp`.
- Fixtures under `fixtures/` are generated by `fixtures/generate.R` only, never hand-edited, and never change in a PR that touches `crates/`, `app/` or `spikes/` (fixture guard in `scripts/check.sh`).
- Every version-creating store write is one transaction; a failed or cancelled import leaves the store unchanged.
- The UI uses only the Epiora component set (`app/src/ui/components/`); CSS uses tokens only; zero axe violations; WCAG 2.1 AA contrast (7:1 in high-contrast themes).
- Budgets: first load (`index.html` + entry JS + CSS + core `.wasm` + `sqlite3.wasm`, each `gzip -9`, summed) < 5,000,000 bytes. All other perf and size thresholds come from the owner after Task 16; no task invents one.
- Desktop: the database key never crosses IPC, never appears in logs or errors, and there is no plaintext fallback.
- No skipped tests (`.skip`, `.only`, `test.fixme`, `#[ignore]`); no number in a test, budget or decision rule changes without an owner escalation.
- Files stay under ~400 lines; a module that grows past that splits by responsibility.

## Review Focus

1. **A re-import where the key column has gained duplicates or blanks:** expect the diff to refuse with `duplicate_key` / `missing_key` naming the first offending line, never a silent merge. → Task 5 `reimport_with_new_duplicate_key_is_refused`.
2. **A dataset whose stored snapshot no longer matches its version hash (bit rot, half-written migration):** expect the run to rebuild from `records` and still produce the right hash, or a typed `HashMismatch` if rebuild also fails — never a result computed on the wrong bytes. → Task 9 `corrupt_snapshot_is_rebuilt_before_run`.
3. **A browser refusing persistent storage or running out of quota mid-import:** expect `quota_exceeded` surfaced in the wizard and the store unchanged (rollback). → Task 8 `quota_error_rolls_back` (conformance, simulated), Task 11 e2e `import shows quota error`.
4. **A second tab or a reload during an import:** expect the second tab to show the lock message and the interrupted import to leave no partial version. → Task 13 `second tab shows lock message`, Task 8 `uncommitted transaction is invisible after reopen`.
5. **Keyboard and screen-reader users on the result cards and data grid:** expect tables with captions and headers, announced results, and full keyboard reach. → Task 12 `keyboard path test`, Task 10 `grid is navigable by arrow keys`.

  pub const SNAPSHOT_FORMAT: u8 = 1;
