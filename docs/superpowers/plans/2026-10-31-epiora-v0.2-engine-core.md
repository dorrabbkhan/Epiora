# Epiora v0.2 Engine Core Implementation Plan

> **Execution:** run by the Epiora conductor (Claude Code, `CLAUDE.md`) delegating each task to a fresh local Devin session (`/epiora-task v0.2 <N>`) and a fresh review session (`/epiora-review v0.2 <N>`). One task per branch, named `v0.2/task-<N>-<short-name>`. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `epiora-core`, a validated, deterministic Rust statistics engine that runs Epi Info's FREQ and TABLES on an in-memory dataset and attaches a receipt to every result, plus its browser binding `epiora-wasm`.

**Architecture:** Two layers joined by `procedures`: `tabulate` turns a `Dataset` into count tables (the only code on the 1M-row hot path), and `stats` holds pure, fixture-validated functions on counts built on `special` (hand-written maths on `libm`). The engine is checked against an R-generated corpus (format v2, tolerance classes) and against Epi Info 7 output, and native and wasm builds must give bit-identical results. `epiora-wasm` only converts types.

**Tech Stack:** Rust stable (exact version pinned in `rust-toolchain.toml`), `libm`, `sha2`, `serde`, `serde_json`, `ryu`, `thiserror`, `proptest`, `criterion`, `wasm-bindgen`, `serde-wasm-bindgen`, `js-sys`, `ts-rs`, `cargo-fuzz` + `libfuzzer-sys` + `arbitrary`, `cargo-deny`, `wasm-pack`, `wasm-opt` (binaryen); Node 22 + Playwright (Chromium); R 4.5.2 under `renv` with `epitools`, `jsonlite`, `DescTools`, `epiR` (fixture generation only, not distributed); GitHub Actions (ubuntu, windows).

**Spec:** `docs/superpowers/specs/2026-10-30-epiora-v0.2-engine-core-design.md` (all sections), with the platform spec `docs/superpowers/specs/2026-10-28-epiora-platform-design.md` §7, §8.3, §12.

## Global Constraints

- Product code lives in `crates/`; nothing under `spikes/` is imported. The only `spikes/` edit in v0.2 is Task 1's `measure.mjs` change (spec E8).
- Licence: AGPL-3.0-only on both crates; `cargo deny check` clean. Rejected outright: GADM data, SQLite SEE, PowerSync.
- Every floating-point function in `epiora-core` goes through `libm`; std `f64` transcendental methods are banned by `clippy.toml` `disallowed-methods` (spec §3.4, E1).
- `clippy::unwrap_used`, `clippy::expect_used` and `clippy::panic` are denied in `epiora-core` outside tests. No input may cause a panic; every failure is an `EngineError` with a stable `code()`.
- Statistically undefined values are `Estimate::Undefined { reason }`, never NaN or infinity. No automatic 0.5 continuity correction on estimates.
- Tolerance classes: `closed_form` 1e-9, `iterative` 1e-6, `ei7_display` = `0.5 × 10^−d` (Epi Info 7 comparisons only).
- Comparison rule (E7): pass iff `|actual − expected| ≤ tol × |expected|`, or `|actual| ≤ tol` when `expected = 0`.
- Fixtures are generated by `fixtures/generate.R` (or, for `fixtures/ei7/`, by its workflow), never hand-edited, and never change in a PR that touches `crates/` or `spikes/` (fixture guard in `scripts/check.sh`).
- The engine reads no clock and no environment at run time; the git SHA is fixed at build time from `GIT_SHA` (fallback `"unknown"`).
- Native and wasm outputs are compared bit for bit, with no tolerance.
- Performance: median of 5 runs of `datasetFromColumns` + stratified `tables` on 1,000,000 rows < 1000 ms in Chromium on `ubuntu-latest`.
- Size: optimised engine `.wasm` ≤ 409,600 bytes after `gzip -9`.
- Files stay under ~400 lines; a module that grows past that splits by procedure.
- Any randomness uses a seeded generator with the seed recorded.

## Review Focus

1. **Zero cells and empty strata:** expect `Undefined { reason }` and listed excluded strata, never NaN, a panic or a silent 0.5 correction. → Task 6 `zero_cell_fixtures`, Task 7 `empty_stratum_is_excluded_and_listed`, Task 12 fuzz targets.
2. **Missing values:** expect per-variable exclusion counts in the result and the receipt, and `include_missing` to add a "(missing)" category. → Task 8 `exclusions_counted_per_variable`, `include_missing_adds_missing_category`.
3. **Native/wasm divergence:** expect the parity diff to fail on one differing bit, and no std float method in `epiora-core`. → Task 1 `float-ban.bats`, Task 10 `parity diff fails on one flipped bit`.
4. **Fixture values that look "close enough":** expect every comparison to use the E7 rule and the fixture's class, and a fixture whose `tolerance_classes` differ from 1e-9 / 1e-6 to be rejected. → Task 1 `compare_*` tests.
5. **Ambiguous 2×2 orientation:** a two-level Text variable without explicit levels is `AmbiguousLevels`, not a guess. → Task 8 `two_level_text_without_levels_is_ambiguous`.

### Task 11a: Exact-method performance (bit-identical)

Owner decision 2026-11-04 (option (a) on PR #27; drafted by the conductor) after Task 11's gate measured a 1879.8 ms CI median
([run 41816557709](https://github.com/dorrabbkhan/Epiora/actions/runs/41816557709)). The budget, workload and
every result stay as they are; only the cost of computing the same bits changes. Conductor stage timings
(native, `opt-level = "z"`, the Task 11 workload, local): `tabulate::cross` 104 ms, `content_hash_hex` 31 ms,
`two_by_two` on the pooled table 504 ms, `stratified` on the three strata 500 ms, `tables` total 1119 ms.
Two causes:
1. `tables` computes `two_by_two` on the pooled table, and `stratified` computes it again as
   `StratifiedStats::crude` on the same sum (only empty strata are excluded, so the sums are equal).
2. `NcHypergeom::weights` evaluates `libm::exp` over the whole support (~490,000 values here) on every
   `brent_root` step. Every term whose exponent `v − max` is below `libm::exp`'s underflow-to-zero point
   contributes exactly `0.0`.
