# Epiora v1.0 Calculators and MEANS Implementation Plan

> **Execution:** run by the Epiora conductor (Claude Code, `CLAUDE.md`) delegating each task to a fresh local Devin session (`/epiora-task v1.0 <N>`) and a fresh review session (`/epiora-review v1.0 <N>`). One task per branch, named `v1.0/task-<N>-<short-name>`. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship v1.0 as a pre-release: every OpenEpi and Epi Info 7 StatCalc calculator from a link (no project, offline, multi-tab), Classic Analysis MEANS on imported datasets, explain mode on every result, a CI-verified R export, the equivalent Epi Info command on every Analysis card, and (G8, added 2026-11-13) a "which calculator?" guide, engine-computed assumption notes and a public validation page.

**Architecture:** `epiora-core` gains `t`/`F`/gamma distributions, MEANS statistics and procedure, a `calc` registry of calculator definitions with one run function each (receipt v3), an `explain` module returning engine-computed traces, and an `export` module writing the dataset CSV, the R script and the Epi Info command. `epiora-wasm` exposes them. The app gains a second, store-less calculator worker behind `/calc` routes that render every calculator generically from the registry, a MEANS dialog, an explain panel with MathML templates, and an R export zip. Fixtures grow by three owner-reviewed families: R (`generate.R`), OpenEpi displayed values (own workflow) and Epi Info 7 MEANS output.

**Tech Stack:** as v0.3 (Rust toolchain from `rust-toolchain.toml`, `libm`, `serde`, `ts-rs`, `proptest`, `cargo-fuzz`, `wasm-pack`/`wasm-opt`; Vite, React, TypeScript strict, React Aria Components, TanStack Router/Query, Comlink, Vitest, Playwright 3 engines, `@axe-core/playwright`), plus `rand_chacha` (random-numbers calculator), `fflate` (export zip), Playwright in `fixtures/openepi/` (capture only), and the renv-pinned R packages Task 1 lists. All at the latest release at task time, pinned in lockfiles.

**Spec:** `docs/superpowers/specs/2026-11-12-epiora-v1.0-calculators-and-means-design.md` (all sections), with the v0.2 spec `docs/superpowers/specs/2026-10-30-epiora-v0.2-engine-core-design.md` §3.4–§4.3, §6, the v0.3 spec `docs/superpowers/specs/2026-11-05-epiora-v0.3-app-shell-design.md` §5, §8, §9, §10, and the platform spec `docs/superpowers/specs/2026-10-28-epiora-platform-design.md` §7.4, §8.6, §12.

## Global Constraints

- Every v0.2/v0.3 rule stands: `libm`-only float maths in `epiora-core` (clippy `disallowed-methods`); no clock, environment or locale reads in Rust; `unwrap`/`expect`/`panic` denied outside tests; every failure a typed error with a stable `code()`; every statistic `Estimate::Value` or `Estimate::Undefined { reason }`, never NaN or infinite; the main thread never touches wasm or SQLite; timestamps only from a worker.
- Tolerance classes are fixed: `closed_form` 1e-9, `iterative` 1e-6 (relative, rule E7); `ei7_display` and the new `openepi_display` = `0.5 × 10^−d`, `d` = displayed decimals, used only for Epi Info 7 and OpenEpi comparisons respectively. An OpenEpi–R or EI7–R disagreement beyond display precision is an owner escalation, never a tolerance change.
- Every statistic any procedure or calculator can emit has a `validation` registry row and at least one fixture (coverage test). Native and wasm outputs are compared bit for bit, including receipts v3, explain traces and export text.
- Fixtures are produced only by `fixtures/generate.R`, the `openepi.yml` workflow (or the owner's human-step capture, same format) and the `ei7.yml` workflow; never hand-edited; never in a PR that touches `crates/`, `app/` or `spikes/` (fixture guard). `.devin/skills/epiora-task/SKILL.md` names v1.0 Tasks 2, 3 and 4 as the fixture tasks.
- Receipts v1 and v2 are byte-for-byte unchanged (golden `crates/epiora-core/tests/golden/receipt_v1.json`) until Task 21's version bump; calculators use receipt v3 (`"calculator"` block instead of `"dataset"`).
- Calculator routes load core-wasm only, in their own worker: no store, no import-wasm, no Web Lock, no database.
- Explain shows only numbers the engine returned in a trace; formula templates carry a source citation; explain texts are marked "pending adviser review".
- Assumption notes (G8, spec §6.1) come only from the engine, use only the rules and thresholds the owner approves in Task 22, never change, hide or reorder a result, and stay outside the receipt hash. The validation page shows only numbers from the `validation-report --format json` output it was built with.
- Exported R scripts call the same R functions that generate the corresponding fixtures (from `fixtures/R/methods/`); the snippets are MIT-licensed with a header line saying so; CI runs and compares them.
- Licence AGPL-3.0-only on product code; `cargo deny check` clean; npm production dependencies pass the v0.3 `license-checker-rseidelsohn --onlyAllow` list. Rejected outright: GADM, SQLite SEE, PowerSync. OpenEpi and Epi Info 7 are references; no OpenEpi code is copied; Epi Info 7 code only with its Apache-2.0 notice (D2).
- Budgets: engine wasm ≤ 409,600 bytes `gzip -9`; first load < 5,000,000 bytes; v0.3 gates `import_1m` ≤ 89,550 ms, `open_tables_1m` ≤ 2,874 ms, import-wasm ≤ 573,616 bytes unchanged; `means_1m` only from the owner's pick after Task 18. No task invents a threshold.
- UI: only the Epiora component set; tokens only; zero axe violations in Chromium, Firefox, WebKit, light and dark; layouts work at 320px and 200% zoom; strings in `app/src/ui/strings.ts` (calculator copy in `app/src/calc/strings.ts`).
- No skipped tests (`.skip`, `.only`, `test.fixme`, `#[ignore]`); no number in a test, budget, fixture or decision rule changes without an owner escalation. Files stay under ~400 lines (`crates/epiora-core/src/corpus/run_case.rs` and `special/gamma.rs` are already at the limit: new code goes in new files).
- Branches `v1.0/task-<N>-<short-name>`; files outside a task's Files block are recorded in `docs/decisions.md` in the same PR.

## Review Focus

1. **A calculator link edited by hand or truncated** (`?a=-3`, `?a=1e400`, `?a=abc`, a missing table row, unknown keys): expect the form to render with each bad input marked and its typed message, nothing computed, no blank page or console error. → Task 14 `malformed_link_marks_inputs`.
2. **MEANS on degenerate columns** — all missing, one non-missing value, a constant column, a group with zero non-missing values: expect `Undefined { reason }` for variance-based statistics and tests, groups with `observations = 0` listed, never NaN, an error or a panic. → Task 6 `degenerate_columns_are_undefined_not_errors`.
3. **Calculator inputs at the edges of the maths** — a sample size whose two proportions are equal, a power calculation with zero effect, counts near 2^53, a zero-event rate: expect `Undefined { reason }` (e.g. `infinite_sample_size`) or a typed input error, never a giant or negative number. → Task 9 `equal_proportions_sample_size_is_undefined`, Task 7 `counts_above_2_pow_53_rejected`, Task 8 `zero_events_rate_ci_defined_lower_zero`.
4. **Exported data with hostile text** — commas, quotes, newlines, non-ASCII, a real text value `"NA"`, an empty-string text value next to a missing value, dates before 1970: expect R to read back exactly the engine's dataset (same values, same missingness) and reproduce the numbers. → Task 17 `csv_roundtrip_hostile_text`.
5. **Two calculator tabs plus the main app open, then the app updated** — expect calculators to keep working in every tab, the main app to keep its lock behaviour, and the update prompt (never a silent swap) in each. → Task 14 `calculator_tabs_coexist_with_app_lock`.

**Interfaces:**
- Consumes: Task 5 `t_*`, `f_sf`, `chisq_sf`; `Dataset`, `RunContext`, `ProcOutput`, `Receipt::new`, registry.
- Produces:
  ```rust
  pub struct MeansOptions { pub variable: String, pub group_by: Option<String>, #[serde(default)] pub include_missing: bool }
  pub struct GroupStats { pub label: String, pub observations: u64, pub total: Estimate, pub mean: Estimate,
      pub variance: Estimate, pub std_dev: Estimate, pub min: Estimate, pub p25: Estimate, pub median: Estimate,
      pub p75: Estimate, pub max: Estimate, pub mode: Estimate }
  pub struct TTest { pub t: Estimate, pub df: Estimate, pub p_value: Estimate, pub diff: Estimate,
      pub diff_ci_95: Ci }                           // v0.2 `stats::estimate::Ci`
  pub struct TwoGroupTests { pub pooled: TTest, pub welch: TTest }
  pub struct Anova { pub ss_between: Estimate, pub ss_within: Estimate, pub ss_total: Estimate, pub df_between: Estimate,
      pub df_within: Estimate, pub df_total: Estimate, pub ms_between: Estimate, pub ms_within: Estimate,
      pub f: Estimate, pub p_value: Estimate }
  pub struct Bartlett { pub statistic: Estimate, pub df: Estimate, pub p_value: Estimate }
  pub struct KruskalWallis { pub h: Estimate, pub df: Estimate, pub p_value: Estimate }
  pub struct MeansResult { pub variable: String, pub group_by: Option<String>, pub groups: Vec<GroupStats>,
      pub overall: GroupStats, pub t_test: Option<TwoGroupTests>, pub anova: Option<Anova>,
      pub bartlett: Option<Bartlett>, pub kruskal_wallis: Option<KruskalWallis>, pub exclusions: BTreeMap<String, u64> }
  pub fn means(ds: &Dataset, opts: &MeansOptions, ctx: &RunContext) -> Result<ProcOutput<MeansResult>, EngineError>;
  pub const MAX_MEANS_GROUPS: usize = 100;
  ```
