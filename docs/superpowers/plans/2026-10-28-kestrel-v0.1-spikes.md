# Kestrel v0.1 Spikes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Test every risky technical bet in the Kestrel spec with cheap, throwaway probes, and record a decision for each before engine work (v0.2) starts.

**Architecture:** Each spike lives in its own folder under `spikes/`, is never imported by product code, and ends in a report under `docs/spikes/` plus an entry in `docs/decisions.md`. A small checker script enforces that every report answers its question with measurements and a decision. Two spikes (R fixture pipeline, sync prototype) produce code likely to be kept; they are still written as probes and promoted only by a later plan.

**Tech Stack:** Rust stable, `wasm-pack`, Emscripten (for mdbtools), Node 22 + Playwright (Chromium), `@sqlite.org/sqlite-wasm`, `@duckdb/duckdb-wasm`, an open SQLCipher wasm build, WebR, Tauri 2, R 4.4+ with `renv`, GitHub Actions (ubuntu, windows, macos runners).

**Spec:** `docs/superpowers/specs/2026-10-28-kestrel-platform-design.md` (§7, §9, §11.1, §12, §14 Phase 0, §17).

## Global Constraints

- Spike code lives only under `spikes/<name>/`; nothing under `spikes/` is imported by any product crate or package.
- Open-core licence is AGPL-3.0; every dependency used in a spike has its licence recorded in its report. Rejected outright: GADM data, the SQLite Encryption Extension (SEE), PowerSync (spec A6, A7, A4).
- Fixtures are never hand-edited and never change in the same commit as engine code (spec §12.1).
- Tolerances: 1e-9 for closed-form results, 1e-6 for iterative fits (spec §12.3).
- Performance budget: 2×2 table on one million rows under 1 s in the browser; first load under 5 MB gzipped excluding WebR and basemaps (spec §12.8).
- Determinism: anything random uses a seeded ChaCha RNG (`rand_chacha`) with seed recorded in the report (spec §7.4).
- Each report states Question, Method, Environment, Measurements, Decision, Consequences, and Licences — `scripts/check-spikes.sh` fails otherwise.
- Commit messages end with the session attribution lines from the repo's conventions.

## Review Focus

1. **A legacy `.mdb` the reader cannot handle** (Access 97/JET3, corrupt or truncated file): expect a clear error naming the format, never a crash or silent empty table. → test in Task 4.
2. **Browser without OPFS** (Firefox private window, older Safari): expect the storage probe to report "unavailable" and the report to name the fallback, not an exception. → test in Task 7.
3. **Edits from devices with skewed wall clocks or identical timestamps:** expect ordering by logical clock and conflicts still detected. → test in Task 9.
4. **R package version drift changing fixture values:** expect CI to fail on any diff after regeneration with pinned versions. → test in Task 5.
5. **Out-of-memory on a low-end device during the million-row benchmark:** expect the harness to record the failure as a measurement and continue with the next query. → test in Task 6.

### Task 9: Sync protocol prototype

**Files:**
- Create: `spikes/sync-proto/Cargo.toml`
- Create: `spikes/sync-proto/src/lib.rs`
- Create: `spikes/sync-proto/tests/simulation.rs`
- Create: `docs/spikes/sync-proto.md`

**Interfaces:**
- Produces (spec §7.3):
  `struct Change { record: u64, field: String, value: String, device: u32, lamport: u64, base_version: u64 }`;
  `struct Device` with `fn edit(&mut self, record: u64, field: &str, value: &str)`, `fn push(&mut self, server: &mut Server) -> PushResult`, `fn pull(&mut self, server: &Server)`, `fn value(&self, record: u64, field: &str) -> Option<&str>`;
  `struct Server` with `fn apply(&mut self, changes: Vec<Change>) -> PushResult`, `fn conflicts(&self) -> &[Conflict]`, `fn resolve(&mut self, conflict_id: u64, winner: &str)`;
  `struct PushResult { accepted: usize, conflicts: Vec<u64> }`.

- [ ] **Step 1: Write the failing tests** in `simulation.rs`:
  `sequential_edits_converge` (A edits, syncs; B pulls; both equal);
  `concurrent_same_field_raises_conflict` (A and B edit the same field offline from the same base → one conflict, both values kept, neither applied silently);
  `concurrent_different_fields_merge` (no conflict, both values present);
  `skewed_clocks_order_by_lamport` (devices with wall clocks 1 hour apart and identical timestamps still order correctly and still detect the conflict);
  `random_interleavings_hold_invariants` (seeded `ChaCha8Rng`, 3 devices, 1,000 seeds × 200 random edit/push/pull/drop-connection steps; after a final full sync and resolution of all conflicts: every accepted change is reflected or recorded in a conflict, every conflict appears in `conflicts()`, all devices equal the server).
- [ ] **Step 2: Run** `cargo test --manifest-path spikes/sync-proto/Cargo.toml` — Expected: FAIL (types missing).
- [ ] **Step 3: Implement** the types in `lib.rs`: Lamport clocks per device, server-assigned per-field versions, conflict when an incoming change's `base_version` is older than the field's current version and the value differs.
- [ ] **Step 4: Run** the tests — Expected: PASS; record test runtime.
- [ ] **Step 5: Write the report**, including what the v2.0 sync spec must add (tombstones, form-version migration, persistence) and a note for D8 (Electric remains a fallback). Run `scripts/check-spikes.sh`.
- [ ] **Step 6: Commit** `spike: sync protocol prototype`.
