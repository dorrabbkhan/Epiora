# Epiora v0.2 — Engine core

**Status:** final draft, owner-approved 2026-10-31 · **Date:** 2026-10-30 · **Owner:** Dorrabb
**Parent spec:** [platform design](2026-10-28-epiora-platform-design.md) §14 Phase 0 ("v0.2 Engine core
(L)"), §7, §8.3, §8.8, §9, §12. **Inputs:** [v0.1 spike index](../../spikes/README.md), "Inputs v0.2 needs".

This spec turns the roadmap line for v0.2 into a buildable design. Where it refines the platform spec, the
refinement is listed in §11 and applied to the platform spec by Task 13 (owner gate).

---

## 1. Intent

**Outcome.** The first product code: a validated, deterministic Rust statistics engine (`epiora-core`) and its
browser binding (`epiora-wasm`), able to run Epi Info's FREQ and TABLES (2×2, stratified 2×2, R×C) on an
in-memory dataset and attach a receipt to every result. No UI, no storage, no import — those are v0.3.

**Who it is for.** v0.3's Analysis workspace (the first consumer), and later StatCalc (v1.0), which reuses the
statistics layer directly on typed-in counts.

**Success criteria.**
1. Every statistic matches the R reference corpus at its tolerance class (§6.2): 1e-9 closed-form, 1e-6
   iterative.
2. FREQ and TABLES on the Oswego data match Epi Info 7's own output at its displayed precision (§6.4).
3. Native and wasm builds produce bit-identical results and receipts on the whole corpus (§5.2).
4. The engine never panics: fuzzing finds no crash; every failure is a typed error.
5. A 2×2 TABLES on one million rows runs in under 1 s in Chromium (platform §12.8), measured in CI.
6. The optimised engine wasm is at most 400 KB gzipped.
7. Every result carries a receipt v1 (§4.3), and every statistic in a result is covered by at least one
   fixture.

**Non-goals for v0.2.** Means, regression and other §8.3 procedures (v1.0); CSV/Excel import and the local
store (v0.3); the `.pgm` interpreter and Epi Info command grammar (v1.2); "reproduce in R or Stata" export
(v1.0); persisting receipts (v0.3); binning of real-valued variables; epidemiologist sign-off (platform §12.9 —
recorded as pending, required before v1.0).

## 3. Architecture

### 3.1 Workspace

Root `Cargo.toml` workspace with members `crates/epiora-core` and `crates/epiora-wasm`; stable Rust; licence
AGPL-3.0-only on both crates; `cargo-deny` for licences and advisories. Nothing under `spikes/` is imported.

### 3.2 `epiora-core` modules

| Module | Purpose |
|---|---|
| `error` | `EngineError` (one enum, `code()` + message). No input can cause a panic. |
| `dataset` | Typed columns, missing values, validation, canonical bytes, content hash |
| `project` | `Project { id, name, datasets: Vec<DatasetRef { id, version }> }` — type only, so receipts can name a project; no storage |
| `special` | Mathematical functions on `libm` (§3.4) |
| `stats` | Pure statistics on count tables (§3.5) |
| `tabulate` | Dataset → frequency table, R×C table, or 2×2 tables per stratum; missing-value handling |
| `procedures` | `freq`, `tables`: tabulate → stats → receipt (§4) |
| `receipt` | Receipt v1 type and canonical JSON (§4.3) |
| `validation` | Static registry: statistic → fixture ids covering it |
| `corpus` (tests and `corpus-runner` only) | JSON loader for `fixtures/data/*.dataset.json`; not a product importer |

Files stay under ~400 lines; a module that grows past that splits by procedure.

### 3.3 Dataset model

```rust
pub struct Dataset { id: String, version: u64, columns: Vec<Column> }
pub struct Column { name: String, data: ColumnData }
pub enum ColumnData {
    Integer(Vec<Option<i64>>),
    Real(Vec<Option<f64>>),
    Text(Vec<Option<String>>),
    Boolean(Vec<Option<bool>>),
    Date(Vec<Option<i32>>),   // days since 1970-01-01
}
```

- `None` is missing (Epi Info's "(.)").
- `Dataset::new` rejects: unequal column lengths, duplicate or empty column names, non-finite reals. NaN and
  infinity therefore never reach the statistics.
- **Content hash:** SHA-256 (`sha2`) over canonical bytes: format byte `0x01`, column count (u32 LE), then per
  column: name (u32 LE length + UTF-8), type tag (u8), row count (u64 LE), then per value a presence byte (0/1)
  followed, if present, by the value (i64 LE; f64 bit pattern LE with `-0.0` normalised to `0.0`; u32 LE
  length + UTF-8; u8 0/1; i32 LE). `id` and `version` are not hashed. A golden test pins the hash of one small
  dataset permanently.
- **Category order:** Boolean → Yes, No; Integer, Real, Date → ascending; Text → ascending by Unicode code
  point (byte order of UTF-8).
- **2×2 orientation:** exposure and outcome levels may be given explicitly. Otherwise, Boolean variables and
  Integer variables whose non-missing values are exactly {0, 1} put Yes/1 first (exposed, ill). Any other
  two-level variable without explicit levels is `EngineError::AmbiguousLevels` naming the variable — never a
  guess.

**Corpus dataset JSON** (`*.dataset.json`, read only by the `corpus` loader):

```json
{ "id": "oswego", "version": 1,
  "columns": [ { "name": "ILL", "type": "boolean", "values": [true, false, null] },
               { "name": "AGE", "type": "integer", "values": [20, 33, null] } ] }
```

`type` ∈ `integer | real | text | boolean | date`; dates are ISO `YYYY-MM-DD` strings; `null` is missing.

### 3.4 `special` — mathematical functions on `libm`

Every floating-point function in `epiora-core` goes through the `libm` crate. `clippy.toml` bans the std `f64`
transcendental methods (`ln`, `exp`, `powf`, `powi`, `sqrt`, `sin`, …, via `disallowed-methods`) in
`epiora-core`, so the rule is enforced by the compiler.

| Function | Method | Reference |
|---|---|---|
| `ln_gamma` | `libm::lgamma_r` | R `lgamma` |
| `normal_cdf`, `normal_sf` | via `libm::erfc` | R `pnorm` |
| `normal_quantile` | Wichura AS241 | R `qnorm` |
| `chisq_sf(x, df)` | regularised upper incomplete gamma: series for x < a+1, Lentz continued fraction otherwise | R `pchisq(lower.tail = FALSE)` |
| `hypergeom_pmf` | log space via `ln_gamma` | R `dhyper` |
| `nc_hypergeom_{pmf, mean, lower_tail, upper_tail}` | log space over the support, normalised — the same construction as R's `fisher.test` internals | tight `generate.R` values |
| `binomial_tail` | summed in log space | R `pbinom` |
| `beta_quantile` | Brent on the regularised incomplete beta (continued fraction) | R `qbeta` |
| `brent_root` | Brent's method, absolute tolerance 1e-14, max 200 iterations; `Err(NotBracketed \| NoConvergence)` otherwise | — |

### 3.5 `stats` — statistics on counts

Every output value is an `Estimate = Value(f64) | Undefined { reason }` and carries a tolerance class.

**2×2 `[[a, b], [c, d]]`** (rows exposed/unexposed, columns ill/well):

| Output | Class |
|---|---|
| Risk (attack rate) in exposed and unexposed; risk difference + Wald 95% CI | closed_form |
| Risk ratio + Wald 95% CI; small-sample adjusted RR CI (as `epitools::riskratio.small`) | closed_form |
| Odds ratio (cross product) + Wald 95% CI | closed_form |
| Chi-square uncorrected, Yates-corrected, Mantel–Haenszel (N−1); df 1; p-values | closed_form |
| Fisher exact p: lower one-sided, upper one-sided, two-sided (sum of table probabilities ≤ observed × (1 + 1e-7), as R) | closed_form |
| Conditional MLE odds ratio; Fisher exact 95% CI; mid-p exact 95% CI; mid-p two-sided p-value | iterative |

**Stratified 2×2 (k strata):** crude 2×2 results; Mantel–Haenszel OR with Robins–Breslow–Greenland 95% CI;
Mantel–Haenszel RR with Greenland–Robins 95% CI; Mantel–Haenszel chi-square uncorrected and corrected with
p-values; Breslow–Day homogeneity test with Tarone's correction (per-stratum expected cell from the quadratic
solution — closed form). All closed_form. Strata with total 0 are excluded from the sums and listed in the
result.

**R×C:** Pearson chi-square, df, p-value; `low_expected` flag when any expected count < 5. closed_form.

**Proportions (FREQ):** per category count, percent, cumulative percent; 95% CI by Clopper–Pearson
(`beta_quantile`) and Wilson. closed_form. Which method is labelled as Epi Info's is decided by Task 9 from the
Epi Info 7 run.

**Undefined, never NaN.** Zero denominators, an empty table, or an unbracketable root give
`Undefined { reason }` with a reason code (`zero_cell`, `zero_margin`, `empty_table`, `not_bracketed`, …). No
automatic 0.5 continuity correction is applied to estimates.

**Property tests (`proptest`):** OR(a,b,c,d) = 1/OR(b,a,d,c) within closed_form tolerance; every defined CI
contains its estimate; every p-value ∈ [0, 1]; MH with one stratum equals the crude estimate; chi-square ≥ 0;
two-sided Fisher p ≥ min of the one-sided p-values; no output is NaN or infinite.

## 4. Procedures and receipts

### 4.1 API

```rust
pub fn freq(ds: &Dataset, opts: &FreqOptions, ctx: &RunContext)
    -> Result<ProcOutput<FreqResult>, EngineError>;
pub fn tables(ds: &Dataset, opts: &TablesOptions, ctx: &RunContext)
    -> Result<ProcOutput<TablesResult>, EngineError>;

pub struct RunContext { pub timestamp: String /* RFC 3339, supplied by the caller */ }
pub struct ProcOutput<T> { pub result: T, pub receipt: Receipt }
```

- `FreqOptions { variables: Vec<String>, stratify_by: Option<String>, include_missing: bool /* false */,
  ci_method: ProportionCi }`.
- `TablesOptions { exposure: VarSpec, outcome: VarSpec, stratify_by: Vec<String>, include_missing: bool
  /* false */ }`, `VarSpec { name, levels: Option<[Value; 2]> }`.
- `TablesResult` is `TwoByTwo { crude, stratified: Option<..> }` when both variables have exactly two levels,
  otherwise `RxC`.
- Excluded records are counted per variable and reported (`exclusions`), never dropped silently.
  `include_missing = true` adds a "(missing)" category instead.
- The engine reads no clock and no environment at run time. The git SHA is fixed at build time by `build.rs`
  from `GIT_SHA` (fallback `"unknown"`).

### 4.2 Tabulation

`tabulate` does one pass over the rows, mapping each variable's values to category indices (a dictionary for
Text), and accumulates `u64` counts. It is the only code on the 1M-row hot path.

### 4.3 Receipt v1

```json
{
  "receipt_version": 1,
  "dataset": { "id": "oswego", "version": 1, "sha256": "…" },
  "procedure": "tables",
  "options": { "…": "canonical, every default filled in" },
  "engine": { "name": "epiora-core", "version": "0.2.0", "git_sha": "…" },
  "validation": [ { "statistic": "odds_ratio.ci_95_fisher_exact", "fixtures": ["2x2/oswego_vanilla"],
                    "tolerance_class": "iterative", "tolerance": 1e-6 } ],
  "exclusions": { "ILL": 0, "VANILLA": 0 },
  "timestamp": "2026-10-30T12:00:00Z",
  "receipt_sha256": "…"
}
```

- Canonical JSON: keys sorted, no whitespace, floats in shortest round-trip form (`ryu`), NaN/infinity
  impossible by construction. `receipt_sha256` is SHA-256 of the canonical JSON with that key omitted.
- `validation` comes from the `validation` registry. A test asserts that every statistic any procedure can emit
  has at least one registry entry, and that every registry fixture id exists on disk.
- A golden receipt test (fixed dataset, options, context and `GIT_SHA`) is byte-identical on native and wasm.

## 5. `epiora-wasm`, parity, performance, size

### 5.1 Binding

Type conversion only — no statistics, no branching on data (platform §7.1). `wasm-bindgen`,
`serde-wasm-bindgen`, `ts-rs` (TypeScript types generated into `crates/epiora-wasm/bindings/`; CI fails on a
diff after regeneration), `wasm-pack build --target web`, `wasm-opt -Oz`, `panic = "abort"` in release.

Exports: `datasetFromColumns(id, version, columns) → DatasetHandle`, `datasetHash(handle)`,
`freq(handle, opts, ctx)`, `tables(handle, opts, ctx)`, `engineVersion()`. Column transfer: Integer →
`BigInt64Array`, Real → `Float64Array`, Date → `Int32Array`, each with a `Uint8Array` presence mask; Text →
dictionary `string[]` + `Uint32Array` codes (`0xFFFFFFFF` = missing); Boolean → `Uint8Array` (0, 1, 255 =
missing). `EngineError` crosses as a JS `Error` with `code` and `message`.

### 5.2 Native/wasm parity (platform §12.5)

The `corpus-runner` binary (native) runs every corpus case and writes one JSON line per case with each f64 as
its 16-hex-digit bit pattern, plus the receipt. `crates/epiora-wasm/parity/run.mjs` does the same through the
wasm build in Node. CI `diff`s the two files: any difference fails. No tolerance.

### 5.3 Performance (E4)

A Playwright test (`crates/epiora-wasm/bench/`) generates 1,000,000 rows in the page from a seeded generator
(seed recorded): Boolean exposure and outcome, 1% missing each, a 3-level Text stratum. Timed:
`datasetFromColumns` + `tables(…)` with stratification; generation excluded. Five runs, median. CI fails if the
median ≥ 1000 ms on GitHub's `ubuntu-latest` runner; timings are uploaded as an artifact. A native `criterion`
bench of the same workload is reported, not gated.

### 5.4 Size (E3)

`scripts/wasm-size.sh` gzips (`gzip -9`) the optimised `.wasm`, prints the byte count, and fails above 409,600
bytes. The size is printed in the CI job summary on every PR.

- `fixtures/stratified/*.json` — Oswego VANILLA × ILL by SEX; one stratum; an empty stratum; a set where

- `fixtures/rxc/*.json` — 3×2 and 4×3 tables.
- `fixtures/freq/*.json` — Oswego SEX and AGE; a variable with missing values, with and without
  `include_missing`.
- `fixtures/ei7/oswego.json` — Epi Info 7 output (§6.4; produced by its own workflow, not `generate.R`).

### 6.2 Fixture format v2 and tolerance classes

Every expected leaf becomes `{ "value": <number|null>, "class": "closed_form" | "iterative" }`; root-found
values also carry `"r_default": <number>` (R's default-tolerance result). `null` means the reference says the
statistic is undefined. The top-level `tolerance` is replaced by
`"tolerance_classes": { "closed_form": 1e-9, "iterative": 1e-6 }`. `fixture.schema.json` is updated to match.

**Comparison rule** (E7; v0.1 did not define it): pass iff `|actual − expected| ≤ tol × |expected|`,
or `|actual| ≤ tol` when `expected = 0`. Relative comparison is stricter than absolute for small p-values.

**Root-found values (E5):** `generate.R` reimplements R's `fisher.test` internals (`dnhyper`, `mnhyper`,
`pnhyper`) and solves with `uniroot(tol = 1e-14)`; mid-p limits likewise. A generation-time check asserts each
tight value agrees with R's default-tolerance value within 1e-2 relative, so a wrong reimplementation cannot
pass silently.

**Drift guard:** the `spike-fixtures` workflow is renamed `fixtures.yml`; it regenerates, validates every
fixture against the schema, and fails on any diff or untracked file.

### 6.3 Engine tests against the corpus

`epiora-core` integration tests load each fixture, run the matching function or procedure, and apply §6.2.
Each failure message names the fixture, the JSON path, expected, actual, and class.

### 6.4 Epi Info 7 check (E2)

- `fixtures/ei7/oswego.pgm`: `READ` `Sample.mdb:Oswego12`; `FREQ SEX`; `TABLES VANILLA ILL`;
  `TABLES VANILLA ILL STRATAVAR=SEX`; `ROUTEOUT` HTML; `QUIT`.
- `fixtures/ei7/run.ps1` (promoted from `spikes/ei7-windows/run-pgm.ps1`; the spike stays untouched) runs it
  with the official 7.2.7.0 build on `windows-latest`.
- `fixtures/ei7/parse.mjs` extracts each labelled number and its displayed decimal count into
  `fixtures/ei7/oswego.json`.
- The workflow runs on `workflow_dispatch` (output committed in Task 3, owner review) and weekly on a schedule,
  failing on any diff.
- Tolerance class `ei7_display`, used only for this file: pass iff `|engine − ei7| ≤ 0.5 × 10^−d`, `d` = the
  decimals Epi Info printed.
- A disagreement between Epi Info 7 and R beyond display precision is an escalation to the owner, never a
  tolerance change.

### 6.5 Fuzzing

`crates/epiora-core/fuzz/` (`cargo-fuzz`, nightly toolchain). Targets: `dataset_json` (corpus loader),
`dataset_columns` (arbitrary typed columns into `Dataset::new`), `freq_any`, `tables_any` (arbitrary datasets
and options). Assertion: returns `Ok` or `Err`, never panics; no output float is NaN or infinite. CI: 60 s per
target on every PR; 30 min per target nightly. Crash inputs are committed under `fuzz/regressions/` and
replayed by an ordinary `cargo test`.

## 8. Error handling

- All public functions return `Result<_, EngineError>`; `EngineError` variants carry a stable `code`
  (`unknown_variable`, `ambiguous_levels`, `empty_dataset`, `invalid_column`, `type_mismatch`, …).
- Statistically undefined values are not errors: they are `Undefined { reason }` inside a successful result.
- Numerical failure inside a root-finder yields `Undefined { reason: not_bracketed | no_convergence }`.
- No `unwrap`/`expect` on paths reachable from input (`clippy::unwrap_used`, `clippy::expect_used` denied in
  `epiora-core` outside tests).
